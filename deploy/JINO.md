# PulseAiPro: сайт на Jino, генерация на Vercel

## Почему гибрид, а не полный переезд

OpenAI не обслуживает Россию: на запрос с российского IP приходит
`403 Country, region, or territory not supported`. Сервер Джино российский, значит вся
генерация — заметки по активам на `gpt-5-mini`, статьи на `gpt-6-astra`, обложки на
`gpt-image-2` — с него работать не будет.

Поэтому та же схема, что уже применена в SellOps: **страницы отдаёт Джино, а крон-задачи,
которым нужен OpenAI, остаются на Vercel**. Оба деплоя смотрят в одну и ту же базу Supabase,
поэтому сгенерированное на Vercel сразу видно на сайте.

У PulseAiPro в OpenAI ходят **все четыре** задачи, поэтому `vercel.json` остаётся как есть,
а на Джино не уезжает ни одной строки расписания.

| | Где живёт |
|---|---|
| Сайт, страницы, картинки, RSS, sitemap | Джино |
| `run-pipeline` ×3 в день (заметки) | Vercel |
| `generate-evergreen` пн/ср/пт (статьи и обложки) | Vercel |
| База, хранилище обложек | Supabase, не переезжает |

**Проект на Vercel удалять нельзя** — на нём держится вся генерация. Домен просто перестаёт
на него указывать; крон Vercel ходит по внутреннему адресу деплоя и от домена не зависит.

## Что пришлось добавить к проекту

1. **`output: "standalone"`** в `next.config.ts` — сборка кладёт в `.next/standalone`
   самодостаточный сервер, его и запускает systemd.
2. **`sharp`** в зависимостях. На Vercel оптимизацию картинок делает платформа; на своём
   хосте без sharp `next/image` отдавал бы оригиналы обложек по 170 КБ вместо 9 КБ.

## Порядок

Сборка делается **на сервере**: `sharp` и SWC — платформенные бинарники, и релиз, собранный
под Windows, тащит `sharp-win32-x64`, который на Linux не стартует. Репозиторий публичный,
сервер клонирует его сам.

### 1. Секреты

    sudo nano /etc/pulsaipro.env
    sudo chown root:www-data /etc/pulsaipro.env && sudo chmod 640 /etc/pulsaipro.env

Образец — `deploy/pulsaipro.env.example`, значения из Vercel → Settings → Environment
Variables. `CRON_SECRET` здесь нужен только для полноты: крон-эндпоинты на этом сервере никто
не дёргает, но код переменную читает.

`OPENAI_API_KEY` на Джино можно оставить пустым — с этого сервера он всё равно нерабочий.

### 2. Установка

    ssh -p 49338 -i ~/.ssh/jino_shared_ed25519 root@73edbea2dac1.vps.myjino.ru
    apt-get update -qq && apt-get install -y -qq git
    git clone --depth 1 https://github.com/grifxxx/pulseaipro.git /tmp/pulsaipro
    bash /tmp/pulsaipro/deploy/install.sh pulsaipro.ru ПОЧТА

Скрипт поставит Node 22, соберёт проект, поднимет службу на 3100, настроит nginx и попробует
выпустить сертификат. Повторный запуск обновляет сайт до свежего master.

### 3. Проверка до переключения DNS

    curl -H "Host: pulsaipro.ru" http://81.177.6.125/

Должен прийти 200 и разметка главной. Пока приходит парковочная страница Джино — DNS не
трогать.

### 4. Переключение домена

Панель Jino → DNS для pulsaipro.ru: запись **A** с вercel-овской `66.33.60.67` поменять на
**81.177.6.125**, и такую же для `www`. TTL обычно 3600 — переключение размазано примерно
на час.

### 5. После переключения

- Сертификат: если certbot на шаге 2 не отработал (DNS ещё смотрел на Vercel), повторить
  `certbot --nginx -d pulsaipro.ru -d www.pulsaipro.ru`.
- **Крон на Vercel не выключать.** Он и есть генерация.
- Убедиться, что на Vercel `NEXT_PUBLIC_SITE_URL=https://pulsaipro.ru`: ссылки в телеграм-канале
  и заявки в IndexNow строятся от неё, и при пустой переменной уедут на адрес вида
  `*.vercel.app`.
- Проверить `/sitemap.xml` и `/feed.xml` на новом хосте по той же причине.
- Вебхук телеграм-бота переставлять не нужно: домен не меняется.

## Обновление сайта потом

    ssh -p 49338 -i ~/.ssh/jino_shared_ed25519 root@73edbea2dac1.vps.myjino.ru \
      'bash /opt/pulsaipro/src/deploy/install.sh pulsaipro.ru ПОЧТА'

## Доступ

Ключ `jino_shared_ed25519` в панели числится как `shared-deploy`, но к уже работающему серверу
она его не применила — отметка и «Сохранить» ничего не поменяли, SSH продолжал отвечать
`Permission denied`. Прописывать пришлось руками через веб-консоль (Облачные серверы → ваш
сервер → Консоль): она пускает в root-шелл без пароля.
